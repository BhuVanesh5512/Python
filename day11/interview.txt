Professional answer :
**PromptProcessor — input preparation and validation**
`PromptProcessor` is responsible for cleaning and validating user input.
For example, it can remove leading and trailing whitespace and raise a `ValueError` if the prompt is empty. 
Validating before invoking the model prevents unnecessary API calls for invalid input.
**AIApplication — orchestration**
`AIApplication` coordinates the application. 
It passes the prompt to `PromptProcessor`, receives the cleaned prompt, and delegates execution to the supplied model.
 It uses dependency injection because the processor and model are provided from outside rather than created internally.
**Model class — model-specific behavior**
The model class implements the operation required by the application, such as `run(prompt)`. 
Different implementations can use different model providers or behavior while following the same interface.
**Testing and extensibility**
I would inject a fake model to test the application without making real API calls.
I would test valid prompts, empty and whitespace-only prompts, the returned result, and whether the model receives the cleaned prompt. 
I would also use assertions so test failures are detected automatically.
To add a new model without modifying `AIApplication`, I would implement the same `run(prompt)` method in the new model and inject its instance. 
This uses dependency injection, composition, and duck typing, reducing coupling and making the application easier to extend and test.
