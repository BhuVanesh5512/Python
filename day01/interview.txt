3.Why do we use virtual environments?
A virtual environment isolates a project's Python interpreter and installed dependencies, reducing dependency conflicts between projects.

9. Why shouldn't .venv be committed to Git?
It's a local, machine-specific environment; the project code and dependency description are what we track.
The reason we don't commit .venv is that the virtual environment contains the actual installed Python environment and can be large, machine-specific, and reproducible elsewhere.
Git stores our project. requirements.txt describes dependencies. .venv is the our local environment we created with given dependencies.
